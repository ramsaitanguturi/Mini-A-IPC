4. EXPERIMENTAL CONTROL AND FAIRNESS

This is the most important requirement.

All implementations must be tested under the same host environment and comparable workloads.

Control the following:

1. Same physical machine.
2. Same operating system and kernel.
3. Same CPU affinity.
4. Same compiler and optimization flags.
5. Same payload sizes wherever supported.
6. Same message count.
7. Same warm-up policy.
8. Same number of repetitions.
9. Same producer/consumer configuration.
10. Same measurement boundaries.
11. Same background workload policy.
12. Same data validation requirements.

Run benchmarks sequentially, not simultaneously.

Randomize the implementation execution order between trials to reduce ordering bias.

Perform cleanup between experiments.

Record the environment before starting.

Do not claim that different IPC mechanisms have identical internal semantics.

For example, shared memory and message queues have different data-transfer and synchronization characteristics.

Define a common application-level benchmark contract:

- Producer generates a payload.
- Payload is transferred using the selected IPC implementation.
- Consumer receives and validates the payload.
- Both sides follow the same logical message protocol.
- Latency and throughput are measured using clearly documented boundaries.

Where a mechanism requires additional synchronization, include it and document the overhead.

For the kernel module, implement or reuse a matched request-response workload if its existing bulk-transfer benchmark is not directly comparable.

If exact equivalence is impossible, classify the results as a separate workload rather than presenting misleading direct comparisons.
